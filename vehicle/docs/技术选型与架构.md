# 车辆调度平台技术选型与架构

## 一、总体架构

车辆调度平台采用 **Monorepo 单仓库** 组织，前端、后端、移动端五个代码项目统一管理。后端拆分为业务服务与定位轨迹服务两个 Node.js 服务：业务服务承载订单、档案、账单等常规业务（MySQL）；定位轨迹服务承载司机端高频定位上报与时空查询（PostgreSQL + PostGIS），独立部署、独立扩容。

```
┌─────────────────────────────────────────────────────────────┐
│                      客户端（3 端）                          │
│  vehicle-web (PC 中后台)  vehicle-order-app (行程申请 H5)   │
│  vehicle-driver-app (Flutter 司机端)                        │
└───────────────┬──────────────────────────┬──────────────────┘
                │ HTTP/JSON                │ GPS 批量上报
                ▼                          ▼
┌──────────────────────────┐   ┌──────────────────────────────┐
│  vehicle-server          │   │  vehicle-location-server     │
│  (NestJS 业务后端)        │   │  (NestJS 定位轨迹服务)        │
│  订单/分配/档案/账单/     │   │  轨迹接收/抽稀/时空查询        │
│  消息/统计/系统/字典      │   │                              │
└───────────┬──────────────┘   └──────────────┬───────────────┘
            │                                 │
     ┌──────▼──────┐                   ┌──────▼─────────┐
     │ MySQL 8     │                   │ PostgreSQL 15  │
     │ 业务数据     │                   │ + PostGIS 3    │
     └─────────────┘                   │ 轨迹/定位时空数据│
                                       └────────────────┘
     Redis 7（缓存/会话）   RabbitMQ（轨迹解耦/通知）   Nginx（静态+反代）
```

外部集成：BPM 审批、UUC/vChat SSO、百度地图（选点/导航/轨迹）、消息推送。

## 二、Monorepo 结构

```
vehicle/
├── vehicle-server/               # 业务后端（NestJS）
├── vehicle-location-server/      # 定位轨迹服务（NestJS）
├── vehicle-web/                  # PC 车辆管理系统（Vue 3）
├── vehicle-order-app/            # 行程申请（Vue 3）
├── vehicle-driver-app/           # 司机端 App（Flutter）
├── docs/                         # 设计文档
├── docker-compose.yml            # 本地基础设施
└── package.json                  # npm workspaces 根
```

## 三、各项目技术栈

### 1. vehicle-server（业务后端）

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 语言/框架 | Node.js 20 + NestJS 10 + TypeScript | 模块化架构，企业级开发体验 |
| 持久层 | TypeORM + MySQL 8 | 订单、用户、司机、车辆、账单、字典、消息、统计 |
| 认证鉴权 | Passport + JWT | 预留 UUC/SSO 集成（工号带出 vChat 信息） |
| 校验 | class-validator + class-transformer | DTO 校验（表单复杂校验场景） |
| 缓存 | Redis（ioredis） | 会话、缓存、分布式锁 |
| 消息 | @nestjs/microservices + RabbitMQ | 轨迹数据解耦、消息通知 |
| 集成 | BPM 审批 SDK、百度地图 Web API、vChat | 审批流、地理编码/路线规划 |
| 测试 | Jest | NestJS 内置 |
| 模块划分 | order（订单/派车/补单）、dispatch（分配）、archives（司机/车辆）、bill（账单）、message（公告）、statistics（统计）、system（用户/字典/权限）、common（公共） | 模块化单体 |

### 2. vehicle-location-server（定位轨迹服务）

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 语言/框架 | Node.js 20 + NestJS 10 + TypeScript | 与业务端同栈，降低维护成本 |
| 数据接收 | HTTP 批量上报 + RabbitMQ 消费 | 司机端聚合上报，异步入库 |
| 数据库 | PostgreSQL 15 + PostGIS 3 | 轨迹点表 + GIST 空间索引 |
| 核心能力 | 轨迹点批量写入、道格拉斯-普克抽稀、ST_Within 圈选查询、ST_MakeLine 轨迹还原、时间段轨迹查询、实时位置查询 | |
| 可选增强 | Fastify 适配器 / WebSocket 长连接 | 若要求秒级实时轨迹 |

### 3. vehicle-web（PC 车辆管理系统）

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3 + TypeScript + Vite 5 | |
| UI | Element Plus | 多标签页、表格右键表头、动态菜单 |
| 状态/路由 | Pinia + Vue Router | 动态权限路由 + 按钮级权限指令 |
| 地图 | 百度地图 JS API | 地图模式/位置/轨迹着色 |
| 图表 | ECharts | 数据统计（车辆/司机/用户维度） |
| 国际化 | vue-i18n | 中英文切换 |
| 网络 | Axios + 拦截器 | JWT 注入、401 跳转 |

### 4. vehicle-order-app（行程申请）

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3 + TypeScript + Vite | 独立多页应用，与 vehicle-web 共用组件包 |
| 地图 | 百度地图 JS API | 选点弹窗、逆地址解析、常用地址 |
| 集成 | UUC SSO 登录、BPM 提交 | 多环境配置（local/dev/test/prod） |
| 表单 | 复杂表单校验 | 15 分钟粒度时间、300KM 距离校验、防重复提交 |

### 5. vehicle-driver-app（司机端）

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Flutter 3.x + Dart | |
| 状态管理 | Riverpod | 轻量、可测试 |
| 地图/导航 | 百度地图 Flutter SDK | |
| 后台定位 | location 插件 + Android 前台服务 | 高频上报 3~10s/点、保活 |
| 本地缓存 | sqflite/Hive | 离线轨迹点缓存 + 断网补传 |
| 网络 | Dio + 拦截器 | JWT、批量上报聚合 |
| 推送 | 厂商推送通道 | 订单通知、公告 |

## 四、数据流关键链路

### 1. 轨迹链路（高频）

```
司机端 App ──GPS 聚合批量上报(3~10s/点)──▶ vehicle-location-server
        ──抽稀/去重──▶ PostgreSQL+PostGIS（轨迹点表，GIST 索引）
PC 端 地图模式/位置/轨迹页 ◀──查询 API（ST_Within 圈选、时间段轨迹）──┘
```

### 2. 业务链路（低频）

```
行程申请 H5 ──提交──▶ BPM 审批 ──▶ vehicle-server ──分配──▶ 司机端接单 ──▶ 行程执行
                                                                    │
                                                    轨迹/账单上报 ──▶ 审核 ──▶ 统计
```

## 五、环境要求

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | >= 20 | 两个后端服务 |
| npm | >= 10 | 包管理（npm workspaces） |
| Flutter SDK | 3.x | 司机端 |
| Docker + Docker Compose | — | 本地基础设施 |
| pnpm（可选） | — | 若前端 workspace 切换 pnpm |

## 六、开发约定

- 后端两个服务统一 NestJS 10 + TypeScript，公共代码（类型定义、常量）放共享目录。
- 前端 vehicle-web 与 vehicle-order-app 通过 workspace 共享组件与工具包。
- 数据库表结构变更以 migration 管理（TypeORM migration）。
- 轨迹点表按定位器 ID + 时间建索引，抽稀在服务端完成后再入库。
