# 管理后台框架 · 能力扩展规划

- 日期：2026-11-12
- 状态：归档用，不参与当前开发
- 定位：**当前方案设计只覆盖 MVP**（见 [方案设计](./方案设计.md)）。本文记录「将来可能要做、但现在不做」的能力、触发条件与预留口子。
- 用法：某项能力出现真实需求时，从本文摘出对应条目，升级为一个 OpenSpec change 再实现；不要直接照本文开工。
- 决策依据：[决策记录](./决策记录.md)

## 0. 已落地快照（2026-11-12）

以下原本属于「后续能力」的项已在 `admin-framework-mvp` 中实现，不再是待办：

- 跨标签页登出同步（localStorage 信号 + storage 事件）

- 表单示例（按钮权限、离开前未保存确认）与列表分页、搜索、空状态
- 版本一致性检查脚本与依赖方向检查
- 页面水印、会话空闲超时、跟随系统主题、页签右键菜单、示例构建分包
- 跨标签页主题同步、跳过导航链接与减少动效适配、表单示例接入 `useForm`
- 列表排序与地址栏同步、离线提示、版本更新提示（`/version.json` 轮询）
- 信息密度（默认 / 紧凑）、请求取消（`AbortSignal`）
- 子应用子路由独立页签与子应用标题、面包屑末级同步
- 表格列宽拖拽与持久化
- 会话过期前倒计时提示与「继续使用」续期
- 缓存页面滚动位置保持、非缓存页面自动回顶
- 命令面板最近访问、登录页版权信息
- 通知中心（可插拔数据源、未读徽标、已读持久化）

仍保留在本清单的 L2 能力：表格查询 URL 同步、字典缓存、三件套组件、上传下载、列配置。

## 1. 分层能力地图


## 2. 判定一项能力该不该进框架

只问三个问题：

| 问题 | 是 | 否 |
| --- | --- | --- |
| 是否在多个项目重复出现？ | 考虑进框架 | 先写在业务里 |
| 是否包含业务语义（审批、订单、报表）？ | 进模板或业务，不进框架 | 可能是框架能力 |
| 是否只有一个页面会用？ | 不进框架 | 再评估 |

补充原则：**出现第二次再抽象**。第一次写下划线，第二次复制粘贴，第三次才抽包。

## 3. 现在留、将来省一次重构的口子

这些即使不实现，形状也要在 MVP 里定死。

| # | 口子 | 当前怎么留（MVP 内） | 不留的后果 |
| --- | --- | --- | --- |
| 1 | 主题令牌 | 布局与组件只用 CSS 变量，不写死色值 | 后期换主题要改所有页面样式 |
| 2 | `me` 契约 | 返回扁平权限码数组 + `roles` + `permissionsVersion` | 后期改契约要所有后端配合 |
| 3 | 路由 meta | 定义为可扩展对象，未知字段透传不报错 | 语义变更会破坏所有已接入项目 |
| 4 | HTTP 信封 | 统一 `{ code, data, message }` 与错误码拦截 | 后期再统一拦截器几乎不可能 |
| 5 | 运行时配置 | 预留 `window.__ADMIN_CONFIG__` 读取入口，MVP 可只读一项 | 一次构建多环境部署要重打包 |
| 6 | `configVersion` | 必填字段 + 迁移函数骨架（当前只有 v1） | 后期升级要全员手工改配置 |
| 7 | 构建版本号 | 构建时注入 `__APP_VERSION__`，页脚可见 | 独立部署后旧 chunk 404 无法定位 |
| 8 | 子应用清单字段 | `entry`、`basePath`、`version`、`healthCheckUrl` 预留（MVP 可不填） | 独立部署出问题只能靠猜 |
| 9 | 子应用可独立运行 | 模板默认支持独立启动，不只支持被挂载 | 事后补会造成子应用结构返工 |

第 1~7 项在 MVP 中只是「写对形状」，不增加功能；第 8~9 项属于模板约束。

## 4. L2 提效能力（有第一个真实页面后）

按性价比排序，实现便宜、收益直接：

| 能力 | 说明 | 触发条件 |
| --- | --- | --- |
| 三件套组件 | Loading / Empty / Error 统一封装 | 出现第 2 个页面 |
| 表格查询 URL 同步 | 分页、排序、筛选写入 query，可分享可刷新 | 出现第 2 个列表页 |
| 请求竞态与去重 | 切换筛选时取消旧请求，重复请求合并 | 出现列表快速切换 |
| 离开确认 | 未保存表单跳转拦截 | 出现第 1 个编辑表单 |
| 字典缓存 | 枚举统一加载与缓存 | 出现第 3 个枚举字段 |
| 格式化工具 | 日期、金额、枚举展示统一 | 出现不一致展示 |
| 列配置 | 列显隐、宽度持久化 | 用户提出诉求 |
| 全局错误边界 | 路由级与组件级兜底 | 首个线上白屏事故 |
| 多标签页登录态同步 | `storage` 事件同步登出/切换用户 | 出现多标签使用场景 |

## 5. L3 企业运维能力（多项目或独立部署后）

| 能力 | 说明 | 触发条件 |
| --- | --- | --- |
| 新版本提示 | 检测到新构建版本时提示刷新 | 独立部署上线 |
| 错误监控接入 | 统一 `onError` 上报到 Sentry 等 | 首次需要线上排查 |
| 埋点 SDK | 路由级与按钮级埋点 | 有数据需求 |
| 子应用健康检查 | 挂载前探测，异常进降级 | 子应用数量 ≥ 3 |
| 灰度与回滚 | 子应用版本按用户/比例切换 | 子应用频繁发布 |
| 打包体积看板 | size-limit 报表进 CI | 体积开始失控 |

## 6. L4 组织级能力（有明确需求后）

| 能力 | 说明 | 成本与影响 |
| --- | --- | --- |
| SSO / OAuth | 替换登录页与 `me` 获取流程 | 中，需改 auth 适配器 |
| 多租户 | `me` 增加 `tenantId`，请求带租户头，子应用切租户需销毁 | 高，影响缓存与子应用生命周期 |
| 数据权限 | 行级/字段级，后端返回数据范围描述 | 高，协议复杂，前端只做展示 |
| 国际化 | 菜单、路由标题、子应用语言同步 | 中，越晚加越贵，MVP 已留 `i18n` 位置 |
| 暗色主题 | 令牌双套 + 运行时切换 | 低，前提是令牌化已做 |
| 移动端适配 | 响应式布局、移动端组件 | 高，布局与交互基本重做 |
| 可视化页面搭建 | 低代码 | 极高，属于另一个项目 |
| 权限管理后台 | 角色/权限点配置界面 | 中高，属于独立后端项目 |
| Module Federation 适配器 | 同栈共享页面/组件，不做沙箱隔离 | 中高，需构建期 federation 配置与版本对齐 |
| 多子应用页签上报 | 子应用上报路由，每个子路由一个页签 | 中，需扩展 bridge 协议 |

---

## 7. 明确不做（长期）

- 自研 UI 组件库。
- 低代码 / 表单设计器 / 页面搭建。
- 权限管理后台界面（只定义契约，不做管理端）。
- SSR。
- 完整监控平台（只做上报接入点）。

---

## 8. 扩展时的推进方式

```
本文某条目出现真实需求
        |
        v
判断是否在 L0/L1 契约上（是 -> 优先做，越晚越贵）
        |
        v
摘出条目 -> openspec-propose 生成 change -> 实现 -> 归档
        |
        v
若改变了公共契约 -> 同时更新方案设计的对应章节
```

原则：**能力可以后加，契约不能后改。** 扩展时优先检查是否触碰 L0。
