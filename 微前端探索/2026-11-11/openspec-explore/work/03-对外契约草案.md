# 03 对外契约草案

> 探索阶段中间产物。以下是 API 草图，用于讨论形状，不是实现。
> 判断标准：业务项目 `main.ts` 能否在 50 行内完成初始化。

## 1. 业务项目视角的最终形态

```ts
// src/main.ts —— 业务项目需要写的全部初始化代码
import { createAdminApp } from '@admin/core'
import { adminPreset } from '@admin/ui'
import { createHttpAuth } from '@admin/auth'
import '@admin/ui/style.css'

import systemModule from './modules/system'

const app = createAdminApp({
  configVersion: 1,
  app: { name: 'console', title: '运营管理后台' },
  router: { base: '/', mode: 'history' },
  auth: createHttpAuth({
    loginUrl: '/api/auth/login',
    meUrl: '/api/auth/me',
  }),
  layout: adminPreset({ logo: '/logo.svg', tabs: true, breadcrumb: true }),
  modules: [systemModule],
  http: { baseURL: import.meta.env.VITE_API_BASE },
})

app.mount('#app')
```

其余都是业务自己的页面文件。没有 `router/index.ts`、没有 `permission.ts`、没有 `App.vue` 布局代码。

## 2. `createAdminApp` 选项

```ts
interface AdminAppOptions {
  configVersion: 1
  app: { name: string; title: string; copyright?: string }
  router?: { base?: string; mode?: 'history' | 'hash' }
  modules?: AdminModule[]
  routes?: AdminRouteRecord[]          // 极简项目可绕过 module 直接给路由
  auth?: AuthAdapter | false          // false = 无权限模式（内部工具）
  layout?: LayoutPreset | false       // false = 自带布局，只用路由与权限
  microApps?: MicroAppDefinition[]    // 可选，来自 @admin/micro
  http?: HttpOptions
  theme?: ThemeOptions
  i18n?: I18nOptions
  hooks?: AdminHooks
}
```

设计取舍：
- `auth: false` 与 `layout: false` 是必要的「逃生舱」，否则内部小工具也得背整套权限。
- `modules` 与 `routes` 二选一即可，前者是推荐用法。
- 不暴露 `router` 实例作为入参（避免业务方提前创建 router 造成时序问题），只给配置。

## 3. 模块协议（route-as-manifest）

**核心决定：路由是唯一事实来源。** 菜单、面包屑、页签、权限、缓存全部从路由 meta 派生，不提供第二份菜单配置。

```ts
// modules/system/index.ts
import { defineModule } from '@admin/core'

export default defineModule({
  name: 'system',
  routes: [
    {
      path: '/system',
      redirect: '/system/user',
      meta: { title: '系统管理', icon: 'Setting', order: 90, permission: 'system:view' },
      children: [
        {
          path: 'user',
          name: 'SystemUser',
          component: () => import('./views/UserList.vue'),
          meta: {
            title: '用户管理',
            permission: 'system:user:list',
            cache: true,          // 参与 keep-alive
            affix: false,         // 是否固定页签
            menu: { icon: 'User', order: 1 },
          },
        },
      ],
    },
  ],
  permissions: {
    // 可选：声明本模块用到的权限点，用于开发期校验拼写
    'system:user:list': '查看用户',
    'system:user:create': '新建用户',
    'system:user:delete': '删除用户',
  },
  setup(ctx) {
    // ctx: { pinia, router, http, auth, bridge, theme, i18n }
    // 注册本模块 store / 全局组件 / 指令，避免业务方再碰 app.use
  },
})
```

`AdminModule` 形状：

```ts
interface AdminModule {
  name: string
  routes: AdminRouteRecord[]
  permissions?: Record<string, string>
  setup?: (ctx: ModuleContext) => void | Promise<void>
}
```

## 4. 路由 meta 契约

```ts
declare module 'vue-router' {
  interface RouteMeta {
    title?: string
    permission?: string | string[]
    permissionMode?: 'any' | 'all'      // 默认 any
    menu?: false | MenuMeta             // false = 不进菜单
    cache?: boolean                     // keep-alive
    affix?: boolean                     // 固定页签
    micro?: string                      // 该路由挂载哪个子应用
    external?: string                   // 外链菜单
    activeMenu?: string                 // 详情页高亮的菜单项
  }
}

interface MenuMeta {
  icon?: string
  order?: number
  group?: string
  hidden?: boolean
  badge?: string | number
}
```

菜单构建规则：
1. 过滤掉 `menu: false`、`hidden: true`、无权限的路由。
2. 父节点若所有子节点都被过滤，则父节点也不显示。
3. 按 `order` 升序，同序按声明顺序。
4. 只有一个子节点的目录折叠为单项（可配置）。

## 5. 微前端定义

```ts
// 来自 @admin/micro，不装则不参与构建
import { defineMicroApp } from '@admin/micro'

defineMicroApp({
  name: 'order',
  entry: '//order.example.com',        // 或 http://localhost:5174
  basePath: '/order',
  mode: 'delegated',                   // delegated | autonomous
  adapter: 'wujie',                    // wujie | iframe | module-federation
  menu: { title: '订单中心', icon: 'ShoppingCart', order: 20 },
  permission: 'order:view',
  props: (ctx) => ({
    token: ctx.auth.token,
    theme: ctx.theme.tokens,
    locale: ctx.i18n.locale,
    permissions: ctx.auth.snapshot(),
  }),
  fallback: () => import('./views/MicroAppUnavailable.vue'),
  timeout: 10_000,
})
```

装配后的路由等价于：

```ts
{
  path: '/order/:pathMatch(.*)*',
  component: MicroAppHost,             // @admin/micro 提供
  meta: { micro: 'order', title: '订单中心', permission: 'order:view' },
}
```

## 6. 生命周期与钩子

```ts
interface AdminHooks {
  onBeforeMount?: (ctx) => void
  onReady?: (ctx) => void
  onRouteChange?: (to, from, ctx) => void
  onAuthExpired?: (ctx) => void
  onError?: (error, info) => void
}
```

顺序：

```
createAdminApp
  -> 校验/迁移配置
  -> 创建 pinia / router / http / i18n
  -> 加载 auth（me）
  -> 构建可访问路由
  -> 注册模块 setup
  -> 注册守卫、指令、全局组件
  -> mount 布局
  -> onReady
```

关键点：**auth 必须在首次路由解析前完成**，否则会出现「先渲染 403 再跳回」。

## 7. 配置版本与升级

```ts
interface AdminAppOptions {
  configVersion: 1       // 必填，缺省时打印告警并按 1 处理
}
```

- 运行时：`normalizeOptions()` 按 `configVersion` 依次迁移，遇到已废弃字段打印带迁移提示的 `console.warn`。
- 构建期：`@admin/cli` 提供 `admin upgrade`，用 codemod 改 API 与配置字段。
- 包版本：`@admin/*` 运行时包固定同版本发布，避免组合不兼容。

## 8. 包划分与依赖方向

```
             +-------------------+
             |    @admin/cli     |  仅开发期，无运行时依赖
             +-------------------+

  +---------------+   +---------------+   +---------------+
  |   @admin/ui   |   |  @admin/auth  |   |  @admin/micro |
  +-------+-------+   +-------+-------+   +-------+-------+
          |                   |                   |
          +---------+---------+---------+---------+
                    v                   v
             +-------------+     +--------------+
             | @admin/core |     | @admin/bridge|
             +-------------+     +--------------+
                    ^
                    |
           vue / vue-router / pinia (peerDependencies)

examples/
  playground/        基座示例（始终跟随最新版，充当契约测试）
  remote-order/      wujie 子应用示例（Vue3 + Vite）
```

规则：
- `core` 只依赖 vue / vue-router / pinia，不依赖任何 UI 库与微前端库。
- `ui` 依赖 core 的类型；不依赖 auth（菜单过滤结果由 core 传入）。
- `micro` 把 wujie 作为 **optional peerDependency**，用户没装 wujie 时使用 iframe 降级。
- `bridge` 不依赖 Vue，可被任意子应用使用。

## 9. 待确认的契约取舍

| 取舍 | 选项 | 当前倾向 |
| --- | --- | --- |
| 布局是否可完全替换 | 配置化 / 组件覆盖 / slot | 配置化 + 组件覆盖，不鼓励整页替换 |
| 路由是否允许业务方直接持有 router | 否 / 通过 `app.router` | 允许只读访问，写操作走 API |
| 权限模式 | 静态路由过滤 / 后端动态菜单 | 静态为主，动态为可选（P2） |
| UI 库 | 绑定 element-plus / 适配层 / 无样式 | 适配层，默认 element-plus |
| 微前端是否进 core | 是 / 否 | 否 |
