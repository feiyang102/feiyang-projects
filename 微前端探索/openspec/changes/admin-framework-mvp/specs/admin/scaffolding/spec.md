# Spec Delta

## Purpose

定义多包仓库的划分、依赖方向与构建发布方式，并提供模板生成能力，使新项目能以统一契约接入且框架可独立升级。

## ADDED Requirements

### Requirement: 包划分与依赖方向
仓库 SHALL 采用多包结构，至少包含核心运行时、界面、权限、微前端、桥接与命令行工具；运行时包 MUST NOT 反向依赖界面或微前端实现。

#### Scenario: 核心包无界面依赖
- **WHEN** 检查核心运行时的依赖
- **THEN** 不包含任何界面组件库或微前端库

#### Scenario: 微前端可选
- **WHEN** 业务项目只安装核心、界面与权限包
- **THEN** 应用可正常构建运行，微前端能力不参与打包

#### Scenario: 违规依赖
- **WHEN** 出现违反依赖方向的导入
- **THEN** 构建或检查阶段失败并指出违规文件

### Requirement: 依赖外部化
运行时包 MUST 将框架级依赖声明为 peer 依赖并在构建时外部化，避免业务项目出现重复实例。

#### Scenario: 重复 Vue 实例
- **WHEN** 业务项目安装框架包并与自身 Vue 一起构建
- **THEN** 产物中只存在一份 Vue 实例，应用正常运行

### Requirement: 子路径导出
包 SHALL 提供明确的子路径导出；重量级可选依赖 MUST 仅在其子路径被引入时加载。

#### Scenario: 未使用微前端
- **WHEN** 业务项目只从主入口导入
- **THEN** 构建产物不包含微前端适配器代码

#### Scenario: 单独引入样式
- **WHEN** 业务项目引入样式子路径
- **THEN** 样式正常生效，且不因导入入口而自动注入

### Requirement: 模板生成
命令行工具 SHALL 生成基座与子应用两类模板；生成结果 MUST 可直接安装依赖并启动。

#### Scenario: 生成基座
- **WHEN** 执行创建命令并选择基座模板
- **THEN** 生成包含初始化入口、示例模块与构建配置的工程，安装后可直接启动

#### Scenario: 生成子应用
- **WHEN** 执行创建命令并选择子应用模板
- **THEN** 生成可独立启动、也可被基座挂载的工程，基础路径与模板配置一致

#### Scenario: 非空目录
- **WHEN** 目标目录已存在文件
- **THEN** 命令拒绝覆盖并提示更换目录

### Requirement: 模块生成
命令行工具 SHALL 支持在既有工程中生成业务模块骨架，包含模块入口与页面组件，并提示注册方式。

#### Scenario: 生成模块
- **WHEN** 执行模块生成命令并传入合法模块名
- **THEN** 生成模块入口与对应页面组件，页面组件名由模块名转换为大驼峰

#### Scenario: 非法或重复模块名
- **WHEN** 模块名不符合命名规范或模块目录已存在
- **THEN** 命令拒绝执行并给出明确原因

### Requirement: 外部工程可安装
框架包 SHALL 能被仓库外的工程通过包管理器安装并运行，MUST 提供类型声明与可用的样式产物。

#### Scenario: 安装打包产物
- **WHEN** 外部工程安装框架的打包产物并调用初始化入口
- **THEN** 工程可构建并渲染后台页面，类型检查通过

### Requirement: 版本一致性
所有运行时包 SHALL 使用同一版本号发布，并在变更日志中标注新增、废弃与破坏项。

#### Scenario: 版本错配
- **WHEN** 业务项目安装的运行时包版本不一致
- **THEN** 启动时输出版本不一致告警，指出不匹配的包
