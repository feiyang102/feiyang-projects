# Spec Delta

## Purpose

以路由为唯一事实来源，派生菜单、面包屑、页签与缓存名单，并支持接口对菜单展示信息的覆盖，保证导航结构可校验、不漂移。

## ADDED Requirements

### Requirement: 路由即清单
框架 SHALL 从路由树派生侧边菜单、面包屑、页签与缓存名单，MUST NOT 要求业务方维护第二份菜单配置。

#### Scenario: 菜单自动派生
- **WHEN** 业务模块注册了带标题的路由树
- **THEN** 侧边菜单按该路由树渲染，层级与标题与路由一致

#### Scenario: 详情页不在菜单中
- **WHEN** 路由标记为不进入菜单并指定了高亮菜单项
- **THEN** 该路由不出现在侧边菜单中，但进入后对应菜单项保持高亮

### Requirement: 菜单过滤规则
菜单 SHALL 只展示有权限且未被标记隐藏的节点；当父节点的所有子节点均被过滤时，父节点 MUST 一并隐藏。

#### Scenario: 子节点无权限
- **WHEN** 用户缺少某节点下所有子节点的权限
- **THEN** 该父节点不显示

#### Scenario: 空目录剪枝
- **WHEN** 目录节点没有任何可见子节点
- **THEN** 该目录节点不显示，不留空白分组

### Requirement: 菜单排序
框架 SHALL 按路由声明的顺序值升序排列同级菜单；未声明顺序时 MUST 保持注册顺序。

#### Scenario: 排序值相同
- **WHEN** 两个同级菜单项声明了相同顺序值
- **THEN** 两者按模块注册的先后顺序排列

### Requirement: 接口菜单覆盖
框架 SHALL 支持从接口获取菜单覆盖项，并按节点标识覆盖标题、图标、顺序与显隐。接口 MUST NOT 新增代码中未注册的页面。

#### Scenario: 覆盖标题与顺序
- **WHEN** 接口返回某节点的标题、图标与顺序覆盖项
- **THEN** 侧边菜单使用覆盖后的标题、图标与顺序

#### Scenario: 未知节点标识
- **WHEN** 接口返回了代码中不存在的节点标识
- **THEN** 框架忽略该项，开发环境输出告警，其余覆盖项正常生效

#### Scenario: 接口不可用
- **WHEN** 菜单接口请求失败或超过超时时间
- **THEN** 框架回退到代码中的静态菜单配置，后台保持可用

### Requirement: 权限过滤在合并之后
框架 SHALL 先合并接口覆盖项，再统一执行权限过滤，两种菜单来源 MUST 使用同一套权限码。

#### Scenario: 覆盖后失去权限
- **WHEN** 接口将某节点设为可见，但当前用户缺少该节点权限
- **THEN** 该节点仍被过滤，不出现在菜单中

### Requirement: 页签与缓存派生
框架 SHALL 根据已访问路由生成页签，并依据路由的缓存标记维护 keep-alive 名单；固定页签 MUST 常驻且不可关闭。

#### Scenario: 打开多个页面
- **WHEN** 用户依次访问多个页面
- **THEN** 每个页面生成一个页签，关闭页签后对应缓存被移除

#### Scenario: 固定页签
- **WHEN** 路由被标记为固定页签
- **THEN** 该页签始终存在且不提供关闭操作
